**Date**: 2026-11-16

## What happened

### DB Migration (20261116000006)
- `user_profiles` (12 cols) — onboarding/personalization data
- `user_follows` (5 cols) — polymorphic follow, **6 target types: event/institution/tag/sector/state/org**
- `user_saves` (5 cols) — same polymorphic structure for bookmarks
- `user_notifications` (13 cols) — in-app notification system
- **Fan-out trigger**: `notify_event_followers()` — AFTER INSERT on event_updates, creates notifications for all users following that event. Security definer.
- 3 enums, ~16 RLS policies

### Follow System (per founder request)
Supports ALL target types from the old system:
- **event** → follow individual opportunity posts
- **institution** → follow educational institutions
- **org** → follow conducting bodies (SSC, UPSC — tags with kind='org')
- **sector** → follow sectors (Banking, Railway — tags with kind='sector')
- **state** → follow jurisdictions (Delhi, Maharashtra — tags with kind='state')
- **tag** → generic tag follow

All use the same `user_follows` table with a `target_type` enum. Follow an event → automatic notification when a new live update is posted (via DB trigger).

### Components
- **FollowButton** — client, optimistic UI, all 6 target types, login redirect if not authed
- **SaveButton** — client, bookmark icon, optimistic toggle
- **NotificationBell** — client, unread badge, realtime subscription (new notifications push live), mark-all-read, dropdown with last 20
